## 1. 目标场景：印刷厂内网 / 离线交付

印刷厂普遍内网隔离、无公网、带宽有限，交付方式为**离线包 + 现场安装**。核心诉求：镜像/依赖可离线、数据不出域、设计稿不外泄、审计合规。

---

## 2. 离线交付方案

### 2.1 交付包结构

```
perp-offline-<version>.tar.gz
├── images/                    # 全量镜像离线包
│   ├── backend-<sha>.tar
│   ├── erp-console-<sha>.tar
│   ├── customer-portal-<sha>.tar
│   ├── supplier-portal-<sha>.tar
│   ├── outsourcing-portal-<sha>.tar
│   ├── ai-service-<sha>.tar
│   └── deps/ (postgres16, redis72, rocketmq5, minio, harbor)
├── deps/                      # 离线依赖缓存
│   ├── npm-cache.tgz / gradle-cache.tgz / python-wheels.tgz
├── manifests/                 # compose / helm / sbom / build-info.json
├── scripts/install.sh         # 现场一键安装
└── checksums.sha256           # 校验
```

### 2.2 离线打包与安装命令

```bash
# 1) 联网环境导出镜像
docker save -o images/backend-${TAG}.tar ${REGISTRY}/backend:${TAG}
docker save -o images/erp-console-${TAG}.tar ${REGISTRY}/erp-console:${TAG}

# 2) 导出依赖缓存（npm/gradle/pip）
tar -czf deps/npm-cache.tgz -C ~/.local/share/pnpm/store .
tar -czf deps/gradle-cache.tgz -C ~/.gradle/caches .

# 3) 生成校验 + 打包
sha256sum images/*.tar deps/*.tgz > checksums.sha256
tar -czf perp-offline-${VERSION}.tar.gz images deps manifests scripts checksums.sha256

# 4) 现场安装（内网机）
tar -xzf perp-offline-${VERSION}.tar.gz && cd perp-offline-${VERSION}
sha256sum -c checksums.sha256
docker load -i images/*.tar
bash scripts/install.sh            # 起本地 Harbor + 推镜像 + compose up
```

### 2.3 本地 Harbor + 内网 Runner + 离线依赖缓存

- **本地 Harbor**：内网机运行 `harbor`，作为离线镜像仓库；交付包镜像先 `docker load` 再 `docker tag` 推入。
- **内网 Runner**：`docker run -d --name runner -v /var/run/docker.sock:/var/run/docker.sock ... ghcr.io/actions/runner`，配置自签名证书信任 Harbor。
- **离线依赖**：npm 用 `pnpm install --offline --store-dir deps/npm-cache`；Gradle 用 `--offline` + 预置缓存；Python 用 `pip --no-index --find-links deps/python-wheels`。

## 3. 数据不出域与设计稿保护

| 措施 | 落地 |
| --- | --- |
| 网络隔离 | 生产段无公网出站（防火墙白名单），AI 敏感数据走**私有化 vLLM**，不调用公有云模型 |
| 设计稿存储 | MinIO 私有桶 + 服务端签名 URL（短时效），下载留痕；禁止直接暴露桶 |
| 传输加密 | 内网 TLS（自签 CA 统一下发）+ `mTLS` 服务间认证 |
| 字段脱敏 | 协同端价格/成本/他客户信息后端 DTO 裁剪（见 [`_conventions.md`](./_conventions.md) §5） |
| AI 输出 | 所有 AI 结论标注"供参考"，设计稿类内容不进入公有云向量库 |

## 4. 备份与灾备

### 4.1 组件与策略

| 组件 | 工具 | 策略 | RPO/RTO |
| --- | --- | --- | --- |
| PostgreSQL | pgBackRest | 全量（每日）+ 增量/WAL 归档（5min），PITR | RPO ≤ 5min，RTO ≤ 30min |
| 对象存储 MinIO | 版本化 + 生命周期 | 每日镜像复制到异地，保留 30 天 | RPO ≤ 24h |
| 配置/密钥 | Vault snapshot / SOPS 文件 | 每日异地冷备 | RPO ≤ 24h |

### 4.2 备份命令

```bash
# pgBackRest 全量 + 归档
pgbackrest --stanza=perp backup --type=full
pgbackrest --stanza=perp backup --type=incr
pgbackrest --stanza=perp archive-push     # WAL 持续归档

# MinIO 版本化（桶策略）
mc version enable local/design-files
mc mirror --watch local/design-files remote/design-files-backup
```

### 4.3 恢复步骤（PITR）

```bash
# 1) 停服务
docker compose stop backend ai-service
# 2) 恢复到指定时间点
pgbackrest --stanza=perp restore --delta --type=time "--target=2025-06-18 09:00:00"
# 3) 启动到恢复模式确认后放行
pg_ctl start -D /var/lib/postgresql/16/main
# 4) 起服务 + 校验数据一致性
docker compose up -d backend ai-service && scripts/verify-restore.sh
# 5) 异地冷备校验（每季度演练）
pgbackrest --stanza=perp verify
```

> 灾备演练：每季度一次"异地冷备 → 空机恢复 → 数据一致性校验"全流程，纳入验收。

## 5. 审计与合规（等保 2.0 三级可裁剪基线）

### 5.1 审计日志

- 所有写操作与越权尝试写入 `audit_logs`（只增不改），**保留 ≥ 3 年**（印刷对账/税务要求，见 [`_conventions.md`](./_conventions.md) §5）。
- 日志落盘不可删：`audit_logs` 表禁用 `DELETE/UPDATE`，归档到 WORM 对象存储（合规留存）。

### 5.2 等保 2.0 三级基线核对表（可裁剪）

| 域 | 条目 | 落地 | 状态 |
| --- | --- | --- | --- |
| 安全物理环境 | 机房出入控制/防盗 | 客户机房门禁 + 监控 | ☐ |
| 安全通信网络 | 分区分域、边界防护 | 防火墙白名单 + 内网 TLS | ☐ |
| 安全区域边界 | 访问控制、入侵防范 | 防火墙 + 入侵检测 | ☐ |
| 安全计算环境 | 身份鉴别（双因素） | TOTP/短信二次验证 | ☐ |
| 安全计算环境 | 访问控制（最小权限） | RBAC + 数据隔离三层 | ☐ |
| 安全计算环境 | 数据完整性/保密性 | 字段脱敏 + 加密存储 | ☐ |
| 安全计算环境 | 剩余信息保护 | 删除即覆盖 | ☐ |
| 安全管理中心 | 集中审计 | `audit_logs` + Grafana | ☐ |
| 安全管理制度 | 制度/岗位/培训 | 提供模板 | ☐ |
| 安全运维管理 | 备份恢复/应急预案 | pgBackRest + 演练 | ☐ |

> 说明：等保 2.0 三级为最高可裁剪基线，印刷厂可依据实际定级（二级/三级）删减；本表 10 项为核心必查项，交付时逐项勾选并留存证据。

## 6. 许可证与开源合规（SBOM + dependency-check）

```bash
# 生成 SBOM（SPDX/CycloneDX）
syft . -o spdx-json=sbom.spdx.json

# 依赖漏洞 + 许可证扫描
mvn org.owasp:dependency-check-maven:check -DfailBuildOnCVSS=7
pnpm license-checker --failOn "GPL;AGPL"      # 传染性许可阻断

# 汇总到交付包
cp sbom.spdx.json manifests/
```

- 交付包必须携带 SBOM；高危 CVE（CVSS ≥ 7）与 GPL/AGPL 传染性许可 = 阻断发布。
- SBOM 与 `build-info.json` 关联（见 [`05-版本管理与分支策略.md`](./05-版本管理与分支策略.md) §7）。

## 7. 资源基线（CPU / 内存 / 磁盘规划）

| 组件 | CPU | 内存 | 磁盘 | 说明 |
| --- | --- | --- | --- | --- |
| backend（erp-server） | 4c | 8Gi | 20Gi | JVM 堆 6Gi，虚拟线程 |
| ai-service（vLLM） | 8c（GPU 可选） | 32Gi | 80Gi | 私有化模型，模型权重 40Gi+ |
| PostgreSQL 16 | 4c | 8Gi | 200Gi（SSD） | 数据 + WAL，预留 3 年审计 |
| Redis 7.2 | 2c | 4Gi | 20Gi | 会话/幂等/锁 |
| RocketMQ 5 | 2c | 4Gi | 50Gi | 事务消息 |
| MinIO | 2c | 4Gi | 1Ti+ | 设计稿/质检图（版本化 ×1.5） |
| Elasticsearch 8 | 2c | 4Gi | 100Gi | 全文检索 |
| 前端（Nginx 静态） | 1c | 1Gi | 10Gi | 四门户 + 小程序 CDN |
| 观测（Prom/Grafana/Loki） | 2c | 8Gi | 200Gi | 指标/日志/链路 |

**整体规划**：一期（Compose 双机）建议 **16c / 64Gi / 2Ti（SSD 混合）**；二期（K8s 三节点）每节点 8c/32Gi + 共享存储，总量 ≥ 24c/96Gi/3Ti。磁盘按 **数据 × 1.5（版本化）+ 备份 × 2（异地）** 预留。
