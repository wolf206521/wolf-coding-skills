# 12 能力整合方案（自研编排层 × 上游执行层）

> 本文定义**如何把下载的上游原版技能与自研 `wolf-*` 技能整合**为印刷行业生成型 ERP（P-ERP）的全过程开发能力。
> 基线见 [`_conventions.md`](./_conventions.md)，总纲见 [`00-master-plan.md`](./00-master-plan.md)，上游来源见 [`../skills/VENDORS.md`](../skills/VENDORS.md)。

---

## 0. 整合原则（两层模型）

```
┌──────────────────────────────────────────────────────────────────────┐
│  编排层 / 领域层（自研 wolf-*，13 个）                                │
│  · 印刷 ERP 领域知识（报价/拼版/排产/多门户/小程序）                   │
│  · 把上游技能串成"大型项目全流程"的编排规则                            │
│  · 补上游没有的工程环节（架构 ADR、脚手架、API 契约、CI/CD、可观测、  │
│    迭代度量、版本发布）                                                │
└──────────────────────────────────────────────────────────────────────┘
                            ▲ 委托 / 编排
┌──────────────────────────────────────────────────────────────────────┐
│  执行层（上游原版技能，18 个，逐字集成）                                │
│  · 真正干活的成熟能力：brainstorming / writing-plans /                │
│    test-driven-development / subagent-driven-development /            │
│    systematic-debugging / webapp-testing / security-code-review /      │
│    frontend-design / requesting+receiving-code-review /                │
│    verification-before-completion / skill-creator / writing-skills /   │
│    mcp-builder / karpathy-guidelines                                   │
└──────────────────────────────────────────────────────────────────────┘
```

**三条铁律**：
1. **上游优先**：能力重叠时以上游原版为准，`wolf-*` 不重复造方法论，只做"领域适配 + 编排"。
2. **wolf-* 不复制上游**：`wolf-*` 的正文若与某上游技能重复，必须改为一行"委托：`REQUIRED SUB-SKILL: <上游技能>`"。
3. **领域归 wolf，方法论归上游**：印刷术语、业务流程、跨端/多租户规则由 wolf 负责；提问、TDD、调试、审查、安全扫描等通用方法论由上游负责。

## 2. wolf-* 技能改造清单

| wolf 技能 | 处置 | 具体动作 |
| --- | --- | --- |
| `wolf-project-kickoff` | **委托** | 新增"委托上游"：提问→`brainstorming`；计划→`writing-plans`；保留印刷需求条目/可追溯性 |
| `wolf-tdd-loop` | **委托** | 新增"委托上游"：RED-GREEN-REFACTOR 循环→`test-driven-development`；保留覆盖率门禁/变异测试的**领域阈值** |
| `wolf-test-automation` | **委托** | 新增"委托上游"：Playwright E2E→`webapp-testing`；保留 k6 性能/契约/小程序自动化的**领域场景** |
| `wolf-security-review` | **废弃** | 顶部加"已废弃，请用 `security-code-review`"，正文保留为历史参考 |
| `wolf-meta-skill-creator` | **降级** | 顶部加"已被 `skill-creator` + `writing-skills` 替代，保留为 wolf 品牌包装" |
| `wolf-architecture-blueprint` 等 8 个 | **保持** | 无上游对应，继续作为领域/工程层，但正文开头加一行"本环节无上游对应，自建"说明 |

> 其余 8 个保持技能：`wolf-architecture-blueprint`、`wolf-domain-modeling`、`wolf-monorepo-scaffold`、`wolf-api-contract`、`wolf-cicd-deploy`、`wolf-observability`、`wolf-iteration-evolve`、`wolf-release-versioning`。

## 3. 全局行为准则

`karpathy-guidelines` 是唯一"始终生效"的行为准则（先问 / 从简 / 精确 / 目标驱动）。落地方式：把其 `CLAUDE.md` 作为本仓库**根级 `CLAUDE.md`**（Agent 启动即加载），并叠加一条"技能路由"提示，见根 [`../CLAUDE.md`](../CLAUDE.md)。
