# 04 · 自动化测试策略（Automation Testing Strategy）

> 对应 Skill：`wolf-test-automation`。技术栈与门禁阈值以 [`_conventions.md`](./_conventions.md) 第 2.4 节为唯一事实源。
> 总纲见 [`00-master-plan.md`](./00-master-plan.md) 第 7 节。本文只做**可执行的落地**，不复述基线。

---

## 1. 目标与原则

1. **测试金字塔**：底层单元测试最多、中层集成/契约次之、顶层 E2E 最少；E2E 只覆盖 P0 不可绕过的业务链路。
2. **契约优先**：前端类型永不由人手工维护，后端出 OpenAPI → 生成 client → 契约测试守门，漂移即阻塞。
3. **AI 必须可评测**：AI 能力不是"上线后再说"，而是把「报价误差 ≤ 3%、幻觉率 ≤ 2%」固化为 CI 门禁，不达标不进主干。
4. **可重复**：所有测试在干净容器内跑，无顺序依赖、无本机隐式状态、无"只有某人机器能过"。

---

## 2. 分层策略与门禁

| 层 | 工具 | 目标 | 门禁阈值（一期，与 2.4 节一致） | 门禁动作 |
| --- | --- | --- | --- | --- |
| L1 后端单元 | JUnit 5 + AssertJ + Mockito | 领域逻辑、纯函数、状态机 | 行覆盖 ≥ 70%，核心域（`quotation/craft/aps`）≥ 85% | 不达标 → 阻断合并 |
| L1 前端单元 | Vitest + Testing Library | 组件、hook、`business-rules` 纯函数 | 覆盖 ≥ 60% | 不达标 → 阻断 |
| L1 架构守卫 | ArchUnit | 模块边界不被破坏 | 跨模块直接依赖内部包 = 阻塞 | 违规即失败 |
| L1 变异测试 | PIT（仅核心域） | 测试质量（非只刷覆盖率） | 变异杀死率 ≥ 60% | 不达标 → 阻断 |
| L2 后端集成 | Testcontainers（PG/Redis/RocketMQ） | 模块间、仓储、事务消息真实链路 | 核心链路 100% 覆盖 | 缺链路 → 阻断 |
| L2 契约测试 | Spring Cloud Contract（服务端）+ Pact（消费端） | 前后端契约一致 | 契约漂移 = 阻塞 | 漂移即失败 |
| L3 E2E | Playwright（Web/H5）+ miniprogram-automator（小程序） | P0 业务链路 | P0 场景 100% 自动化 | 未覆盖 → 阻断 |
| L4 性能 | k6（接口）+ JMeter（报表/批处理） | 容量与响应 | P95 < 500ms（查询）/ < 2s（复杂报表） | 超阈值 → 阻断上线 |
| L4 安全 | Trivy + Semgrep + OWASP Dependency-Check + ZAP | 镜像/依赖/代码/运行时 | 高危 0 容忍 | 高危即失败 |
| 静态质量 | SonarQube Quality Gate | 技术债与缺陷 | 新增 Blocker/Critical = 0 | 阻断 |
| AI 评测 | Ragas + 黄金集 + 人工抽检 | AI 输出质量 | 报价误差 ≤ 3%，幻觉率 ≤ 2% | 不达标 → 阻断上线（见 §6） |

> **分层执行位置**：L1/L2 在 PR 阶段跑（快，< 10 min）；L3/L4/AI 评测在 `staging` 部署后跑（慢，< 30 min）。见 [`06-CICD与部署.md`](./06-CICD与部署.md)。

## 3. 测试数据管理（印刷行业 fixtures）

所有样例数据集中在 `tests/fixtures/`，**禁用手写 SQL 散落各处**。数据必须：可重复装载、带语义命名、能表达行业边界（克重、开数、放损、印色、后道）。

### 3.1 目录与样例

```
tests/fixtures/
├── paper/                        # 纸张物料
│   ├── paper_coated_157gsm_889x1194.json      # 铜版纸 157g 大度
│   ├── paper_offset_80gsm_787x1092.json       # 胶版纸 80g 正度
│   └── paper_imported_250gsm_700x1000.json    # 进口 250g 特种
├── craft/                        # 工艺/BOM
│   ├── craft_cover_lamination_gloss.json      # 封面覆亮膜
│   ├── craft_binding_saddle.json              # 骑马订
│   └── craft_post_diecut.json                 # 后道模切
├── order/                        # 订单样例
│   ├── order_book_5000_copies.json            # 书刊 5000 册
│   ├── order_box_corrugated.json              # 包装彩盒
│   └── order_urgent_48h.json                  # 48h 加急单（触发排产优先级）
├── quotation/                    # 报价黄金对
│   ├── quote_golden_*.json                    # 输入（产品/尺寸/数量） + 期望价格区间
└── _loader/
    └── seed.py / SeedData.java                # 统一装载器，按环境注入
```

### 3.2 命名规范

- `{领域}_{特征}_{关键参数}`，如 `paper_coated_157gsm_889x1194`。
- 报价黄金集命名为 `quote_golden_<id>`，id 三位数，对应评测报告可追溯。
- 每条 fixture 必须带 `_meta`：`owner / created_at / purpose / 关联需求号`。

### 3.3 数据一致性

- 集成测试用 Testcontainers + Flyway 迁移后，由 `_loader` 注入 fixtures；**不共享开发库、不依赖手工状态**。
- 打印尺寸用毫米、克重用 g/m²、数量用"份/册/张"，字段名与领域模型一致，避免口径漂移。

## 4. 测试环境隔离（Testcontainers）

```java
@Container
static PostgreSQLContainer<?> PG = new PostgreSQLContainer<>("postgres:16")
    .withDatabaseName("perp_test").withUsername("perp").withPassword("perp");

@Container
static GenericContainer<?> REDIS = new GenericContainer<>("redis:7.2").withExposedPorts(6379);

@Container
static GenericContainer<?> MQ = new GenericContainer<>("apache/rocketmq:5.3")
    .withExposedPorts(9876, 10911);
```

规则：
- 每个集成测试类 = 一套独立容器拓扑，测试结束销毁，**不落本地**。
- `RocketMQ` 事务消息、`Redis` 幂等键、`PostgreSQL` RLS 策略都在容器内真实验证。
- CI 中启用 Ryuk 回收残留容器；本地通过 `~/.testcontainers.properties` 关闭遥测以加速。

## 5. E2E（Playwright + miniprogram-automator）P0 场景清单

P0 = 业务不可中断链路。下表**至少 12 条**，覆盖四门户 + 小程序，每条一个可执行的 spec 文件。

| # | 端 | 场景 | 关键断言 |
| --- | --- | --- | --- |
| 1 | ERP 后台 | 登录 + 二次验证（TOTP） | 登录成功、会话建立、审计写入 |
| 2 | ERP 后台 | 创建报价单并触发 AI 报价 | 报价单落库、AI 建议标注"供参考" |
| 3 | ERP 后台 | 报价 → 转销售订单 | 订单状态 `submitted`，事件 `order.sales-order.submitted` |
| 4 | ERP 后台 | 生成工艺卡 + 排产甘特 | 工艺路线完整、机台占用可见 |
| 5 | 客户侧 Web | 手机验证码登录 + 下单 | 只能见本租户/本合作方单据 |
| 6 | 客户侧 Web | 查询订单进度 | 进度状态正确、价格字段脱敏 |

| 8 | 供应商侧 | 接收采购单并报价回传 | 供应商仅见自己采购单、报价回写 |
| 9 | 供应商侧 | 上传纸张质检照片 | 文件关联采购单、状态流转 |
| 10 | 外协侧 | 接外协单 + 上传工序照片 | 外协单状态更新、附件关联 |

| 12 | 客户小程序 | 微信授权登录 + 下单 | 与 Web 同口径（同一 portal-core） |

## 6. AI 评测：把「误差/幻觉」变成自动化门禁

### 6.1 黄金集（Golden Set）

`tests/fixtures/quotation/quote_golden_*.json`，每条约含：

```json
{
  "id": "quote_golden_001",
  "input": { "product": "精装书", "size_mm": [185, 260], "pages": 320,
              "quantity": 5000, "cover": "铜版纸 250g 覆膜", "inner": "胶版纸 80g" },
  "expected_price_range": [12800, 13500],
  "forbidden_claims": ["需人工确认的事项不得虚构"]
}
```

### 6.2 自动化门禁（Ragas + 断言）

```bash
# 1) 跑评测（Ragas 指标：忠实度/上下文召回 + 自定义报价误差）
python tests/fixtures/_loader/eval_quotation.py \
  --golden tests/fixtures/quotation \
  --output build/eval/quotation_report.json

# 2) 断言门禁（不达标 → 非零退出 → CI 阻断）
python tests/fixtures/_loader/gate_eval.py \
  --report build/eval/quotation_report.json \
  --max-price-error 0.03 --max-hallucination 0.02
```

### 6.3 指标口径（必须可复现）

| 指标 | 计算 | 门禁 |
| --- | --- | --- |
| 报价误差（MAE%） | `mean(abs(预测价 - 实际价) / 实际价)` | ≤ 3% |
| 幻觉率 | 输出中出现黄金集 `forbidden_claims` 或无法追溯到 RAG 来源的比例 | ≤ 2% |
| 忠实度（Ragas faithfulness） | 输出是否被检索上下文支撑 | ≥ 0.9（参考线） |

- 黄金集每次业务规则变更（报价规则表）后同步更新并打版本，避免"门禁永远绿"。
- 人工抽检：每双周随机 50 条线上真实问答入库，扩充黄金集；财务/价格类结论必须人工确认后才生效（见 [`00-master-plan.md`](./00-master-plan.md) §5 安全红线）。

## 7. 性能测试场景（k6 / JMeter）

| 场景 | 工具 | 负载 | 阈值（2.4 节） |
| --- | --- | --- | --- |
| 报价单查询 / 订单列表 | k6 | 200 VU，Ramp 1min，持续 5min | P95 < 500ms |
| AI 报价接口（SSE） | k6 | 50 VU 并发 | P95 < 2s（流式首字 < 1s） |
| 复杂报表（月对账/成本） | JMeter | 20 并发批处理 | P95 < 2s |
| 排产重算（APS） | JMeter | 100 工单批量 | 完成时间 < 60s |

```bash
# k6 冒烟
k6 run tests/performance/quotation-smoke.js --env BASE_URL=https://staging.example.com
# JMeter 批处理报表
jmeter -n -t tests/performance/report-month.jmx -Jhost=staging.example.com
```

结果写入 `build/perf/*.json`，P95 由脚本断言，超阈值返回非零退出。

## 8. 命令示例（本地 + CI 统一入口）

```bash
# 后端单测（含覆盖率，门禁在 JaCoCo 报告）
./gradlew test jacocoTestReport

# 前端单测 + 契约
pnpm test && pnpm test:contract

# E2E（指定端）
pnpm --filter @perp/e2e test:e2e --project=erp-console
pnpm --filter @perp/e2e test:e2e --project=customer-portal
pnpm --filter @perp/e2e test:e2e --project=customer-mini   # miniprogram-automator

# 集成（Testcontainers）
./gradlew integrationTest

# 安全
trivy image --severity HIGH,CRITICAL <image>:<tag>
semgrep scan --config=auto --error

# AI 评测
python tests/fixtures/_loader/gate_eval.py --max-price-error 0.03 --max-hallucination 0.02
```
