# 澄清式提问问题库（Question Bank）

按 Karpathy 四原则组织。提问时优先封闭式/选择题，把开放问题收窄；答案未明确处继续追问。

## 1. 先问（Ask First）

- 这个需求解决谁的什么问题？不解决会怎样？
- 现状是怎么做的（手工 / 旧系统 / 无）？痛点在哪一步？
- 需求来自哪份文档/原型？路径、页码、图编号？

## 2. 从简（Start Simple）

- 最小可用版本（MVP）只包含什么？
- 哪些是"必须做"，哪些是"以后再说"？
- 去掉这个功能，核心流程还能跑通吗？

## 3. 精确（Be Precise）

| 维度 | 追问点 |
| --- | --- |
| 用户/角色 | 谁用？角色权限？是否外部协作方（客户/供应商/外协）？ |
| 数据量级 | 用户数、日订单量、单据行数、附件大小、保留年限 |
| 并发/性能 | 峰值 QPS、P95 延迟目标、复杂报表耗时 |
| 数据隔离 | 是否多租户？合作方级隔离？字段级脱敏（价格/成本）？ |
| 合规审计 | 审计保留年限（默认 ≥ 3 年）、是否等保、数据是否出域 |
| 误差阈值 | 报价误差、幻觉率等 AI 类指标的具体数值 |

## 4. 目标驱动（Goal-driven）

- 这个需求的业务目标是什么？用什么指标衡量？
- 与 master-plan 中哪条 DoD 目标对齐？
- 验收时如何证明"目标达成"（可复现的测量方式）？
