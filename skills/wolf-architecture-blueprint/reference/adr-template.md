# ADR 模板

文件名：`docs/<project>/adr/NNNN-<kebab-case-title>.md`（NNNN 四位递增编号）。

```markdown
# NNNN. <标题>

- 状态：提议 / 已接受 / 已废弃（被 ADR-NNNN 取代）
- 日期：YYYY-MM-DD
- 决策者：<角色/人>

## 背景（Context）

描述要解决的问题、约束（私有化/合规/团队技能）与触发原因，附量化指标。

## 选项（Options）

| 选项 | 优点 | 缺点 |
| --- | --- | --- |
| A | … | … |
| B | … | … |
| 现状 | … | … |

## 决策（Decision）

选择哪个方案 + 理由（为何其余不选），一句话可复述。

## 后果（Consequences）

- 正面：…
- 负面/代价：…
- 需要配套做的事：…

## 回滚条件（Rollback）

何时判定失败、如何回退、回退成本。
```

## 模块化单体 → 微服务 的拆分触发指标（示例）

任一满足即启动拆分评估，并另立 ADR：

- 某模块发布频率显著高于整体，发布窗口互相阻塞（用部署频率度量，见 `00-master-plan.md` §11）。
- 两模块团队在同一代码区持续冲突，PR 平均合并时间超阈值。
- 某模块需独立扩缩容且资源特征与整体差异大（如 AI 服务已独立进程）。
- 某合作方数据有法律/合同强隔离要求，模块化单体的 RLS 无法满足。
