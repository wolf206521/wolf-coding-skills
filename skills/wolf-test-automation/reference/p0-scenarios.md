# P0 场景清单模板

## 规则

- **P0** = 影响核心业务主链路（下单、报价、拼版、排产、质检、发运、对账、登录）的场景。
- 每个场景必须有：编号、前置数据、步骤、期望结果、依赖服务、自动化状态。
- 新功能上线前必须登记；清单中**不得存在「未自动化」的 P0 场景**。
- 清单文件提交到 `tests/e2e/p0-scenarios.md`，与用例代码一一对应。

## 场景字段

| 字段 | 说明 |
| --- | --- |
| 编号 | `P0-<DOMAIN>-<NN>`，如 `P0-ORDER-01` |
| 名称 | 一句话场景名 |
| 前置数据 | 依赖的 fixture（见 `tests/fixtures/`） |
| 步骤 | 可执行步骤（Given/When/Then） |
| 期望 | 可断言的客观结果 |
| 依赖服务 | 所需后端/AI/外部系统 |
| 自动化 | `playwright` / `miniprogram` / 待办 |

## 示例清单

| 编号 | 名称 | 前置数据 | 步骤 | 期望 | 依赖服务 | 自动化 |
| --- | --- | --- | --- | --- | --- | --- |
| P0-ORDER-01 | 客户下单生成工单 | 客户 fixture、纸张库存 | 登录→新建订单→提交 | 订单已提交，工单生成 | erp-server、RocketMQ | playwright |
| P0-QUOT-01 | AI 报价误差 ≤ 3% | 黄金集报价样例 | 上传产品图→报价 | 报价与基准误差 ≤ 3% | ai-service | playwright |
| P0-IAM-01 | 越权访问被拒 | 供应商账号、客户订单数据 | 供应商访问客户订单 | 返回 403 | erp-server | playwright |

## 维护

- 每双周 Sprint 复盘清单：删除失效场景、补新场景、复查自动化状态。
- 新增领域能力（如外协、对账）时，先补清单再写用例，避免「先开发后补测」。
